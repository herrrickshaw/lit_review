Both prior Wednesday passes landed on the mailer's top-5 cut. This one pointed somewhere the
register had never looked: `portfolio_builder.py`, which runs a Markowitz optimiser on

- **Doing-right (verified):** `fund_implementability.py:5-12,33-36` already tests what

  toward cheap names. `portfolio_builder.py:191-201` already shrinks expected returns
  (James-Stein, λ=0.5).
- **Not a new gap:** the raw sample covariance at `portfolio_builder.py:217` is **queue item
  18** already (opened 2026-08-28, revisited 2026-09-12). Not re-queued. Added one
  qualification — at the default `--max-holdings 25` against LOOKBACK=504, T/N ≈ 20, so item
  18's conditioning concern is mild *at this call site*.
- **Gap (the day's finding):** `portfolio_builder.py:285-286` concatenates the three pick
  buckets, dedupes, and truncates `[:25]`. `load_picks()` (`:62-100`) fills those buckets in
  workbook **row order** and sorts by nothing. So the optimiser's universe is "the first 25
  rows", and if `Triple_Hits` alone has 25+ names the other buckets are dropped silently —
  `:287` prints the final count only. Same disease as the mailer's top-5 cut, different site,
  and cheaper to test here because the output is a portfolio with a measurable Sharpe.

for a fixed asset set, and there is no point polishing an estimator whose input set is
