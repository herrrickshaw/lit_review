Root cause

market-pipeline is not its own git repo — it is a directory inside the $HOME repo, which the batch driver deliberately skips (107 GB). So it never entered the graph the normal way. It entered as a GitHub clone instead, and the merge script keyed graphs by path, appending both. The 13-node clone silently shadowed the 3,223-node local graph that had been sitting on disk since 27 July.

Fixed in graphify_merge_direct.py by keying on repo name with an explicit priority — a local checkout always beats a shallow clone — plus a hook for local trees that are not their own repo.

05

Turning the graph on the other repos

The same comparison that caught the market-pipeline stub, run across all 63 repos. It found the bug twice — and the second time the first fix was not enough.

Fingerprinting each repo by its set of (filename, symbol) pairs and comparing every pair produced five repo pairs at 100% overlap. Three of them turned out not to be duplicates at all: they were one GitHub repo counted twice, because the local checkout sits in a directory named differently from its own remote.

Keying on the name was not enough — key on the remote

The first fix deduplicated by directory basename, which cannot see these: the two names genuinely differ. Re-keying the merge on the normalised origin URL collapsed them. The graph dropped from 69 repos to 63, and from 137,848 nodes to 134,094 — but the sharper correction is the reuse index, which fell from 8,475 shared symbols to 5,604. Roughly a third of the cross-repo "code reuse" signal was a repo being compared against itself.

Collapsing the aliases leaves the finding that actually matters standing — two pairs of genuinely distinct GitHub repos holding identical code:

Below that sits a family that is partly shared rather than forked — the market repos, where consolidation is a design question rather than a cleanup: global-market-data ~ global-stock-screener at 70.9%, ~ stock-screener-platform at 58.4%, ~ market-pipeline at 52.1%. The shared surface is concrete and named: is_trading_day(), trading_days(), turnover(), z_score_normalise(), load_universe() — a market-calendar and factor-primitives layer that exists five times.

Two things the scan did not justify

Orphaned code is not a problem here. Unreferenced definitions run under 1.2% in every repo above 60 symbols — there is no dead-code cleanup worth doing.

The "god file" list is mostly a false positive. Its top two entries are REPO_INDEX.json at 215 "definitions" — a data file being counted as code. The real ones are test files and market-pipeline/…/specifications.py at 56.

06

Rebuilding it

All extraction is local tree-sitter parsing — no API tokens, no network. Only the bridge step reads both graphs together.

# 1. per-repo AST graphs (44/48 repos built, ~19,700 nodes)
python3 ~/.ruflo/scripts/graphify_all_repos.py

# 2. market-pipeline is not its own git repo — graph it explicitly
graphify update ~/market-pipeline --no-cluster

# 3. union into the cross-repo map (dedup by REMOTE, local beats clone)
python3 ~/.ruflo/scripts/graphify_merge_direct.py

# 4. parse the registers and resolve file:line into the code graph
python3 /Users/Shared/lit_review/tools/build_lit_graph.py

# 5. turn the graph on the repos themselves (stubs, twins, god files, orphans)
python3 /Users/Shared/lit_review/tools/diagnose.py
